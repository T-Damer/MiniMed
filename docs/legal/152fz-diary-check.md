# Дневник и 152-ФЗ: сверка с чек-листом методички

Сверка подключаемого дневника (сервер в Yandex Cloud, приложение врача и пациента) с чек-листом
[методички по 152-ФЗ](152fz-guide.md). Сделана разработчиком по коду и документам репозитория 2026-11-11.
Это не юридическая консультация: оценки «закрыто» и «пробел» нужно подтвердить у юриста клиники-оператора.

Как распределены роли (ADR-0026, «Consequences»): оператор персональных данных — медицинская организация, разработчик
обрабатывает данные по её поручению (ст. 6 ч. 3). Часть пунктов чек-листа — обязанности оператора, а не кода. Данные
пациентов — о здоровье, то есть специальная категория (ст. 10).

## Что уже закрыто

| Требование | Как в дневнике | Где в репозитории |
| --- | --- | --- |
| Хранение в РФ (ст. 18 ч. 5) | База YDB и API в Yandex Cloud `ru-central1`; DNS Cloudflare без прокси | ADR-0026 §8, `docs/DIARY_ADMIN.md` |
| Согласие отдельным документом (ст. 9 ч. 1) | Три документа присоединения с версиями; принятие с текстом и временем хранится в зашифрованной записи `consent` | `apps/app/src/features/diary/consent/joining-documents.ts`, `docs/diary-consent/` |
| Письменное согласие на данные о здоровье (ст. 10) | Бумажная подпись на приёме плюс принятие в приложении | ADR-0026 «Consequences»; подтвердить у юриста, достаточно ли электронного принятия |
| Отдельное согласие на исследование | Добровольное, с текстом этического комитета; отказ и отзыв не меняют лечение | `consent/study-consent.ts` |
| Отзыв согласия (ст. 21 ч. 5) | Кнопка «Отозвать согласие» на телефоне пациента сразу удаляет записи, ключи и привязки, телефоны отключаются | `DELETE /api/device`, `withdraw` в `sqlite-store.ts` / `ydb-store.ts` |
| Защита данных (ст. 19) | Сквозное шифрование: сервер хранит только шифротекст; доступ к пациенту только у кураторов | ADR-0026 §3, §7 |
| Логи без ПД | Метод, маршрут, код, время; без тел, токенов и идентификаторов | ADR-0026 §10 |
| Разграничение доступа | Роли куратора (владелец, редактор, читатель); читатель не пишет; обзор сервиса только для адресов из `DIARY_ADMIN_EMAILS` | ADR-0026 §5, `docs/DIARY_ADMIN.md` |
| Минимизация | Пациента на сервере нет по имени: случайный id, псевдоним только в шифротексте; итоги врачей — только суммы | ADR-0026 §7 |
| Обезличивание для анализа | «Выгрузка для исследования»: коды вместо имён, дни наблюдения вместо дат, без свободного текста | `dashboard/diary-cohort-export.ts` |

## Пробелы

| Требование | Что не так | Кто закрывает |
| --- | --- | --- |
| Политика обработки ПД на сайте (ст. 18.1) | На страницах дневника нет ссылки на политику ни у врача, ни у пациента | Оператор пишет политику; разработчик добавляет ссылку на страницы |
| ПД врачей | Почта, имя и хеш пароля врача хранятся на сервере в открытом виде, но при регистрации врача нет ни согласия, ни ссылки на политику (`DoctorSignIn.tsx`) | Разработчик: строка согласия при регистрации; оператор: текст |
| Уведомление РКН (ст. 22) | Обновить сведения оператора: цели, категории, место хранения | Оператор (вопрос 4 в `personal-data.draft.md`) |
| Договор поручения (ст. 6 ч. 3) | Только черновик | Оператор и разработчик |
| Срок хранения после окончания наблюдения | В черновике предложено удаление через [30] дней, автоматического удаления нет: дневник удаляется только при отзыве согласия или врачом | Решение юриста, затем код |
| Резервные копии | YDB хранит автоматические копии 2 дня: после отзыва согласия шифротекст ещё до 2 дней лежит в копиях (в пределах 30 дней ст. 21 ч. 5) | Записать в политику |
| Инциденты (ст. 21 ч. 3.1: 24 и 72 часа) | Нет регламента: кто замечает, кто и в какие сроки уведомляет РКН | Оператор; разработчик описывает свою часть в `docs/DIARY_ADMIN.md` |
| Push через Google и Apple | Адреса подписок — идентификаторы устройств; уведомления без ПД. Нужно подтвердить, что это не трансграничная передача (ст. 12) | Юрист (вопрос 5 в `personal-data.draft.md`) |
| Уровень защищённости (ПП № 1119) | Специальная категория, меньше 100 000 субъектов — в упрощённой таблице методички УЗ3; нет модели угроз и акта уровня защищённости | Оператор с ИБ; разработчик даёт описание системы (ADR-0026) |
| Правила работы с обезличенными данными | Выгрузка для исследования есть, письменных правил нет | Оператор и этический комитет |
| Сертифицированный антивирус и СЗИ | Сервер — бессерверный контейнер в Yandex Cloud; применимость требований к такой схеме не разобрана | ИБ оператора |
