# QA pass UX13, 2026-10-08

Tester role: a doctor on a phone, report only (no code changed, nothing committed).

## Scope and method

- Build under test: local `main` at 14000ba8 (fast-forwarded from the originally created worktree at 378b28e8 after the coordinator's correction; every finding from the old build was discarded). `bun run build:app`, `vite preview` on 127.0.0.1:4191.
- Driver: Playwright 1.62 / Chromium with `--mute-audio` and fake microphone, persistent profile (OPFS kept between scripts). Phone pass 375x812, DPR 2, touch (`isMobile`, `hasTouch`); one desktop pass 1280x900; dark pass at 375.
- Motion was judged from Playwright video and 6-10 fps contact sheets (ffmpeg), timings from DOM sampling every 100-250 ms.
- Network: the core (440 MB) is served from localhost, so core timings are best-case. Module downloads went to raw.githubusercontent.com (real network).
- Not tested: a physical phone, Android WebView, real microphone/model transcription, the `Создать хранилище` chip (needs a patient vault), the news article in-app reader and adding a feed by URL (sources are blocked by CORS in the web build, see N1), assessments run-through and most medical calculators (only the unit converter was opened), ECG manual path, imaging viewer beyond its entry sheet, the knowledge graph.
- Sanitized env: the preview server inherited the shell environment (the harness refused `env -i`); the app is a static build and receives no non-`VITE_` variables. No API keys were used.
- The interface rules were read in `AGENTS.md` (the worktree copy contains them at 14000ba8), plus `docs/DOCTOR_UX.md`, `docs/CLINICAL_UX.md`.

Severity: P0 data loss or unusable; P1 main task broken or misleading; P2 clear defect or rule violation a doctor notices; P3 polish.

## What works well

- Search is one loading state: skeleton → results about half a second after the last keystroke, no loader/skeleton flip (the old-build flicker is gone); expanding «Найдено ещё в N фрагментах» animates smoothly; clearing the field cross-fades to the home.
- The tools strip stays under the field during search; after starring tools «Все инструменты» becomes icon-only.
- Installing a module from a result chip never disturbs the visible results (chip → ring → gone, search button spins briefly).
- History re-runs a query; back from a document returns to the results with the query intact.
- Reader: page bubble «N / 104» with go-to input, rolling counter while scrolling, controls hide on scroll down, TOC with page numbers, wide tables scroll sideways under a finger while vertical swipes still scroll the page.
- Vaccination page: title row with «?» and a live paper thumbnail, compact patient row, status counters, time-line grid with a «сейчас» marker, «Лист для мамы» print preview; birth-date-only entry exists in the patient sheet.
- Forms: compact patient row, progress bar, draft state, thumbnail in the header, required-field jump on «Сохранить», preview with the unfilled-field count.
- Drug interactions: progressive input (second field appears after the first), missing-instruction case offers the exact download inline; the dictionary tool offers its download in a sheet.
- No horizontal overflow at 375 px on any visited screen; dark theme is coherent; desktop keeps a centred phone-width column with a two-column result grid.
- Console clean except the items above (`HEAD core.db ERR_ABORTED` is the app's own probe and harmless).
