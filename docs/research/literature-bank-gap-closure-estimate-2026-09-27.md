# Личная библиотека `Med/`: оценка закрытия пробела определений по оглавлениям (2026-09-27)

Оценка того, сколько из **~7 141–7 144** названий без определения можно закрыть выдержками из
`Med/`. Уточнение координатора после первого прохода: **OCR не делаем**; вместо этого — там, где
уже есть текстовый слой PDF или уже готовый OCR-черновик, можно прочитать **оглавление** и
сопоставить его пункты с незакрытыми названиями, для приоритизации. Это по-прежнему только оценка:
никакого дословного извлечения определений в этой сессии не делалось.

## Первый вывод не изменился: anatomy закрыть нельзя

`docs/LITERATURE_BANK.md` явно относит `Med/Анатомия`, `БХ`, `Биология`, `Гистология`, `Иммунка`,
`Микра`, `ПФ`, `ПатАн` к «Not relevant to MiniMed's clinical scope» — решение владельца библиотеки,
не техническое ограничение. Anatomy (1 414, крупнейший раздел пробела) остаётся недостижимым через
`Med/` независимо от следующих находок.

## Новая находка: библиотека почти вся уже читаема без OCR

Проверка (только структура — количество символов текстового слоя на первых страницах каждого PDF,
без обращения к оставшемуся тексту и без сохранения содержимого) по всем `.pdf` в `Med/`:

| | Файлов |
|---|---:|
| Всего PDF в библиотеке | 548 |
| Уже с текстовым слоем (не скан, OCR не требуется) | **434 (79%)** |
| Только скан (нужен OCR, который сейчас не делаем) | 114 |

Это меняет предыдущую оценку: раньше я считал, что почти вся педиатрическая литература ждёт
«второго пакета OCR» и поэтому недоступна. На деле подавляющее большинство файлов уже цифровые —
предыдущая оценка отражала три уже распознанных файла ПДБ, а не реальный состав библиотеки.

Это ТРИ книги из 434 с текстовым слоем. Совпадение не одинаковое по книгам (Шабалов Т1 дал всего

## Пересмотренная оценка

Экстраполировать линейно (59 × 434/3) было бы нечестно — пересечения между книгами по одной теме
(неонатология) велики, а Шабалов показал, что не каждая книга даёт сопоставимую плотность. Честная
оценка:

- **Педиатрически-профильные книги с плотным по-нозологическим оглавлением (по образцу Володина/
  «Трактовки анализов»), таких в библиотеке по классификации `LITERATURE_BANK.md` порядка
  10–15** (Нео/Литература ×5 оставшихся, ДетскиеБолезни, часть ФП/ДХ/ГП/Эндо/Фтиза/ЛОР/Офтальм,
  Нутрициология, лабораторные/диагностические справочники наподобие уже проверенного) — реалистично
  **несколько сотен (порядка 150–350) уникальных названий**, в основном из категорий
  conditions/syndromes/diagnostics/endocrinology/hematology/pharmacology, а не из anatomy.
- Это по-прежнему **приоритизация, не закрытие**: список названий, для которых стоит поискать
  дословную выдержку с указанием книги/издания/страницы, а не готовые определения. Формат учебника
  (глава/раздел, а не «термин — определение») означает, что для каждого найденного названия ещё
  нужно вручную найти конкретный абзац с определением внутри соответствующей главы — это
  сопоставимо по трудоёмкости с MSD (см. `definition-quote-budget-2026-09-27.md`), не быстрее.

## Что не делалось (по прямому ограничению задачи)

- Тела глав не читались и не сохранялись — только страницы с самим оглавлением, только чтобы
  получить список заголовков.
- Ни один скан не отправлялся на OCR.
- Ни один текст, выдержка или файл из `Med/` никуда не скопирован и не закоммичен;
  `literature-toc-matches.json` (список совпадений с указанием книги) — только в
  `/private/tmp/.../scratchpad`, вне репозитория.

## Предлагаемый следующий шаг (требует решения пользователя)

1. Список 59 уже найденных названий (и их книги) можно передать редактору для целевого дословного
   поиска определения — без OCR, эти 3 книги уже читаемы.
2. Если результат нужен шире — прочитать оглавления ещё ~10–15 профильных книг с текстовым слоем
   тем же способом (несколько минут на книгу, без OCR и без сохранения тела текста) и повторить
   сопоставление; я не стал делать это для всей библиотеки в этом чекпоинте, чтобы не расширять
   объём без явного запроса.
3. Дальше — как и раньше: дословное извлечение отдельно найденных определений с книгой/изданием/
   страницей, спорные случаи — в `LITERATURE_REVIEW_QUEUE.md`, сами книги и выдержки не
   коммитятся, если `LITERATURE_BANK.md` не разрешает явно.
