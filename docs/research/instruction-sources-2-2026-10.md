# Где ещё лежат официальные инструкции: второй обход (2026-10-03)

Задача: официальные тексты (ГРЛС PDF, ОХЛП ЕАЭС, листки-вкладыши) для 8 325 регистраций, которые ГРЛС отдаёт медленно (CAPTCHA после 40–50 регистраций в сутки). Продолжение [grls-mirrors-2026-10.md](grls-mirrors-2026-10.md), [manufacturer-instructions-2026-10.md](manufacturer-instructions-2026-10.md), [data-sources-2026-10.md](data-sources-2026-10.md); контекст — [GRLS_INGESTION_HANDOFF.md](../GRLS_INGESTION_HANDOFF.md). Повторяю из них только то, что нужно для вывода.

Режим: только исследование. Малые выборки, последовательные запросы с паузой 3–5 с, truthful User-Agent `MiniMed-research/1.0 (personal single-user offline medical reference; sequential, rate-limited)`, `robots.txt` прочитан до запросов, CAPTCHA и логины не трогались, массовых загрузок нет. Код, данные и каталог репозитория не менялись. Рабочие файлы удалены.

Обозначения: ✔ — проверено мной в этой сессии (запрос, расчёт, чтение оригинала); ◐ — проверено помощником-исследователем и принято по его отчёту (я перепроверил только отдельные пункты, они помечены ✔); ○ — пересказ или сниппет, оригинал не читался.

## 1. Короткий вывод

1. **Полного альтернативного хранилища официальных текстов нет**; дословных копий PDF ГРЛС в аптеках, датасетах и приложениях я не нашёл.
2. **Самая полезная находка — реестры Беларуси и Казахстана**: для ЕАЭС-досье регистрационный номер общий (`ЛП-№(000092)-(РГ-RU)` = `ЛП-№000092-ГП-KZ` = `ЛП-№000092-ГП-BY`), и `rceth.by` (листок и ОХЛП PDF) и `register.ndda.kz` (JSON-API, docx/PDF) отдают тот же общий документ без CAPTCHA, `robots.txt` без правил ◐. Пересечение с нашими пробелами: **361 регистрация (≈4,3 % из 8 325; ЖНВЛП 184)**, из них только BY — 177, только KZ — 85, оба — 99 ◐.
3. **Три новых сайта производителей** вместо «TLS-блока» из M1: `ns03.ru` (Северная звезда), `dalkhimpharm.ru` (Дальхимфарм), `avexima.ru` (Авексима). До ≈150 регистраций по совпадению названий (верхняя оценка; реалистично ≈100) ✔. Российский корневой сертификат для этого **не нужен**: причины «TLS-ошибок» были другими (§4).
4. **Платный путь есть, но без цен**: ЛС ГЭОТАР (API по договору, заявляют ежедневное обновление из ГРЛС), РЛС Aurora (18 249 инструкций, API/офлайн-копия), база Видаль для разработчиков (Access/API; текст отредактирован, не дословный) ◐/✔ (§5–6). Видаль краулить нельзя: пользовательское соглашение п. 4.3 требует предварительного согласования (§5).
5. **Аптеки и маркетплейсы не дают PDF** и не годятся как «официальный дословный текст»: нет ни одной ссылки на `.pdf`/`InstrImg`, тексты перепечатаны, часть устарела, условия запрещают копирование ◐ (§3). Побочная польза: `routingGuid` карточек ГРЛС (zdravcity, eapteka) и номер РУ в `srtNum` (apteka.ru).
6. Основной легальный путь прежний: **запрос в НЦЭСМП/ГРЛС** (до 77 %). Новые бесплатные пути вместе с пилотом M1 дают порядка **8–9 % недостающего** (§8).

## 4. TLS-контейнер: результат

Метод ✔: `docker run --rm --user $(id -u):$(id -g)` на локальном образе `node:24-bookworm-slim` (как в `scripts/fetch-nsi-dictionary.sh`; секреты не передавались, смонтирована только рабочая папка вывода). Внутри корневой сертификат «Russian Trusted Root CA» скачан с `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`, отпечаток SHA-256 `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31` совпал с опубликованным (срок до 2032-02-27) и подключался только в параметре `ca` отдельного соединения. В хост-систему ничего не ставилось, `curl -k`/`rejectUnauthorized:false` применялись только в диагностической пробе рукопожатия (без передачи запросов) и для чтения цепочки. Для каждого хоста: DNS, рукопожатие с системными корнями, с корнем Минцифры, при ошибке — дополнение цепочки по AIA (как делает браузер), затем `robots.txt`, главная, sitemap.

**Главный итог: корень Минцифры не понадобился ни одному из 30 проверенных хостов.** Ни у одного сайта рукопожатие не проходило только с ним. Причины «TLS-блока» из M1 оказались иными:
