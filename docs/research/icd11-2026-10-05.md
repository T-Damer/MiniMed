# ICD-11 (МКБ-11, ВОЗ): sources, licence, Russian text and the optional module — 2026-10-05

Task ICD11 (STATE.md). Owner decision 2026-10-05: «МКБ-11 could be a separate pack; Russia uses
МКБ-10 now.» This document is the source and rights check that precedes any build, then records what
was built. Nothing was machine-translated, no account or API client was created, no licence
click-through was accepted.

## Short answer

- **A lawful Russian text is obtainable without an account**: WHO publishes the ICD-11 MMS
  linearization in Russian (browser page marked as a full, non-prerelease language) and offers the
  «Spreadsheet file» in Russian as a public download from `icdcdn.who.int`. It is WHO's own Russian
  translation, not ours.
- **What it contains is narrower than the full ICD-11 entity**: code, Russian title (+ WHO's
  English title), class kind, chapter, residual flag, hierarchy, coding note. It has **no
  definitions, no inclusions/exclusions, no index terms, no postcoordination axes**. Those exist only
  behind WHO's ICD-API (cloud API needs a registered client; the local Docker/Windows/Linux
  deployment needs none but needs the owner to accept the ICD API licence by flag). See
  «What the owner must decide».
- **ICD-10 ↔ ICD-11 mapping tables are published openly by WHO** (same page, no login) and are in the
  module as links between cards. They are English-only on the WHO side.
- Russia does not use ICD-11 (see below); the module is therefore optional, labelled
  «МКБ-11 (ВОЗ), справочно; в РФ действует МКБ-10», and ICD-10 stays the default everywhere.

## Licence (what it allows and what it does not)

CC BY-ND 3.0 IGO for «the Classifications» (codes, URIs, descriptions, digital version):

- allowed: using and incorporating the classification into software, storing and transmitting codes,
  titles and URIs; commercial use; adding data fields **if clearly identified as not originating from
  WHO**; attribution «International Classification of Diseases, Eleventh Revision (ICD-11), World
  Health Organization (WHO) 2019»;
- not allowed: modifying the classification or using it to develop or promulgate a different
  classification; removing WHO notices;
- **not covered** by the Classifications licence and subject to a separate written WHO agreement:
  «mapping or producing crosswalks between other classifications … and producing translations».

Consequences for MiniMed:

1. Titles, hierarchy and coding notes are WHO's published Russian text, carried **unchanged**; every
   chunk cites the raw file's SHA-256 and the line it came from. Where WHO's Russian title cell is
   empty the WHO English title is shown and the card says so. No translation, harmonisation or
   summary is generated (owner declined machine translation).
2. Fields MiniMed adds (document ids, links to МКБ-10 cards, labels) are marked as ours in metadata
   (`rights.note`); the module does not feed ICD-11 into any ICD-10 structure.
3. **Crosswalks**: the licence names crosswalks as outside the Classifications licence. The tables
   shipped here are not ours: they are WHO's own published tables, copied row by row with source line
   refs, unchanged; we make no mapping of our own. WHO's redistribution terms for those tables are
   **not explicit** (the `mapping.zip` readme has no licence text). They are therefore recorded as an
   owner publication decision (`publicationDecision`, personal project, `requiresReview`), the same
   mechanism as the other experimental reference modules in `docs/REFERENCE_SOURCE_POLICY.md`, not as
   a rights clearance. Removing them is one flag in the preparer if the owner prefers.
4. Citation text is stored in every document's `rights.citation` and printed in its «Источник» section.

## Russian availability and status in the Russian Federation

- WHO's MMS Russian version exists and is public (above). Which institution produced the translation
  is not stated on WHO's page; the published sources found do not name it (Medvestnik 2021: the
  Ministry's interdepartmental working group, order № 385 of 2021-04-22, planned the translation as the
  first of four stages; the consortium-psy article describes Russian clinicians taking part in
  forward/back translation of the ICD-11 clinical guidelines; institution and date not stated).
- **No Russian official publication** (Минздрав / ЦНИИОИЗ) of ICD-11 was found. The only Russian
  implementation signal is negative: on 2024-02-03 the Ministry suspended the transition (reported by
  Zona.media: «не соответствует духовно-нравственным ценностям», ICD-10 of 1990 remains in force); ICD-10 stays in force. The
  WHO English text is the authoritative one; the Russian text is a translation whose legal status in
  the Russian Federation is none.
- Hence the label, the optional status and the practice note on every card: «В Российской Федерации
  действует МКБ-10. Код МКБ-11 не заменяет код МКБ-10 в документах.»

## What the public files contain

`SimpleTabulation-ICD-11-MMS-ru.txt` (UTF-8 with BOM, CRLF, tab separated, coding notes may contain
line breaks): 37 052 rows = 28 chapters + 1 360 blocks + **35 664 categories with codes** (17 704 rows
are in chapter X, extension codes, 159 in V).

| Field | Present | Note |
| --- | --- | --- |
| code, class kind, chapter, depth, residual flag, leaf flag | yes | blocks and chapters have no code (block id like `BlockL1-1A0`) |
| Russian title | 35 558 of 37 052 | **1 494 rows have no Russian title** (mostly chapter 26 traditional medicine 711, chapter X 640, chapter 14 skin 42): English title kept, marked, never translated. 685 more Russian cells are Latin-only names (organisms, «COVID-19») and are WHO's text as is |
| English title | yes | kept next to the Russian one |
| coding note | 633 rows (630 in Russian) | «Указание по кодированию» |
| hierarchy | yes | `Parent` = foundation URI; residual rows (`…/other`, `…/unspecified`) share the foundation URI of their parent entity, so identity is the **linearization URI** |
| groupings, primary tabulation | yes | not carried (the hierarchy covers it) |
| definition, inclusions, exclusions, index terms, postcoordination axes | **no** | API/browser only |

Mapping tables: `11To10MapToOneCategory` (17 943 rows, all join), `10To11MapToOneCategory` (12 597;
68 point at a foundation entity that is not in the MMS linearization — empty ICD-11 code, e.g. the ICD-10 neoplasm-of-uncertain-behaviour rows — and are reported, not linked),
`10To11MapToMultipleCategories` (15 630, 25 such unlinked rows; every single-category row is repeated, so the card shows only the rest). Mapping to a **cluster** such as `A00.0 → 1A00&XN8P1` is the only postcoordination
data in the public files; it is shown as text on the stem card, the extension codes are named with
their titles from the same tabulation. ICD-10 titles in WHO's tables are English only; the card shows
them as «название ВОЗ на английском» and links to our own МКБ-10 card by code when that card exists.

## What the owner must decide

1. **Definitions, inclusions, exclusions** (the substance of the ICD-11 entity). They are not in any
   public file. Two lawful routes, both his to start: (a) register a free ICD-API client on
   `icd.who.int/icdapi` himself and give the build a token path (not created by an agent); (b) run
   WHO's local deployment `whoicd/icd-api` — no registration, but the container needs
   `acceptLicense=true` (an acceptance of WHO's licence terms), pulls an image from Docker Hub and runs
   it, so it was not started. Unknown until tried: whether the container serves Russian definitions
   (`include=2026-01_ru`) or only English ones. If only English exists, those fields stay out
   (no translation).
2. **Crosswalk redistribution**: keep as shipped (owner publication decision, WHO tables unchanged), or
   drop the «Соответствие МКБ-10» sections.
3. **Publication**: done by the task as the owner asked: the pre-release asset `reference-icd11-2026.10.5`
   is uploaded and the module is in the catalog preview with `minAppVersion` 0.6.51 (the first app with
   the ICD-11 scope and label handling, so older apps never see it). To withdraw it: delete the catalog
   entry (`minimed.reference.icd11.ru`) and the release.

## Update 2026-10-06 (ICD11b): ICD-API text, kept crosswalks, smaller pack

   inclusions, exclusions and the other textual properties the API serves in Russian are merged into

### The container

`docker run -d --name minimed-icdapi -p 127.0.0.1:8382:80 -e acceptLicense=true -e include=2026-01_ru
whoicd/icd-api` (image `whoicd/icd-api@sha256:1b77eb6d…1b7c`, 330 MB on disk, built 2026-03-06; data
`cloud_2026-01-17_release-icf-mms_en-ru` loaded at start, about 50 MB downloaded; API `v2.6.0`). Port
bound to loopback only; `saveAnalytics` is off by default («Saving Analytics is OFF» in its log), so no
query text leaves the machine. The container is stopped and removed when the fetch is done (the image
stays). It serves `GET /icd/release/11/2026-01/mms/<linearization id>` with headers
`Accept-Language: ru`, `API-Version: v2` (without the release in the path it answers 404).

Fetch: `bun run content:fetch:icd11-api` (`medbase fetch-icd11-api`), bounded concurrency (4), loopback

### What the container serves, and what is in Russian

Every string is tagged `"@language": "ru"`, **including English fallback**. WHO marks untranslated
strings with a trailing `[No translation available]` (residual rows also
`[Residual translation rule not defined]`) and its proposed, not confirmed, Russian strings with
`[possible translation]`; some English definitions come without any marker. The API title of the
1 494 untranslated rows is the marker string, so the tabulation stays the only source of titles.

Rules in code (`icd11_api_text.py`, tests with real cached answers):

- `[No translation available]` → English fallback, **omitted** and counted;
- definition / long definition / fully specified name / coding note with no Cyrillic letter and no
  marker → English served unmarked, **omitted** and counted;
- `[possible translation]` → WHO's Russian text, kept with the visible note «(пометка ВОЗ: possible
  translation)»;
- inclusions, exclusions, index terms that are Latin-only and unmarked (organism names,
  abbreviations) are WHO's own Russian-version text and are kept as served, like the 685 Latin-only
  titles of the tabulation;
- an unknown translation marker stops the build; line breaks inside a label become spaces, nothing
  else is rewritten; an index term equal to the card's own title is not repeated.
