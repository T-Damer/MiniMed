# Kolibri-1 (Aleph Alpha) — evaluation for MiniMed, 2026-10-05

Verdict: **do not try** for any on-device role. Not an embedding model, not a reranker, 78B MoE
(78 GB / 47.5 GB at Q4), English and German only, no Russian evaluation. Reconsider only if Aleph
Alpha ships a small dense variant or an embedding/reranker model.

## 1. What it is

| Item | Finding |
|---|---|
| Task | Decoder-only chat/reasoning LLM (`pipeline_tag: text-generation`, `Kolibri1ForCausalLM`, vLLM). Reasoning effort none/low/medium/high, tool calling, long context, RAG with "grounding with abstention". Not an embedding or reranker model. |
| Architecture | Mixture-of-Experts transformer, 50 layers, 384 routed experts per layer, 6 routed + 1 shared expert per token. **78.1B total, 3.46B active** per token (4.4 %). 128k-token custom UniBPE vocabulary tuned for German morphology. |
| Languages | **English + German only.** Pre-training mix about 62.5 % English, 21–24 % German, 13.6 % code; 24T tokens in total. SFT pool is 92.6 % English, 5.0 % German, 2.4 % "other languages" (tech report, SFT data pool, p. 64). The report contains **no Russian** benchmark, tokenizer-efficiency figure or data statement (full text searched). Russian quality is therefore unknown and expected to be weak or accidental; the tokenizer is not built for Cyrillic. |
| Context | 262,144 native, extendable to 1,048,576. |
| License | Apache 2.0 on the weights only ("other artifacts excluded"). Commercial use and redistribution are allowed. The inference package `aleph-alpha-inference` is a separate artifact. |
| Release | HF repo created 2026-10-02; blog announcement 2026-10-03; pre-training finished 2026-09-11. |
| Intended use | Assistants, agents and document processing "where a person reviews the output"; explicitly not for unsupervised operation. Known risks listed: hallucination, bias, outdated knowledge, anthropomorphisation. |

## 2. Sizes, formats, on-device feasibility

- Official: BF16/FP8 safetensors, 32 shards, **78.1 GB** (77.4 B parameters in FP8, 0.7 B in BF16). Requires at least 2x A100/H100 80 GB.
- Community quantizations (13 listed on the HF model tree): GGUF Q4_K_M **47.5 GB**, Q8_0 83.1 GB (Hob-forge); MLX 2/3/4/6-bit; NVFP4/MXFP4 about 40 GB; GPTQ W4A16. No ONNX or transformers.js build. No quantization below about 40 GB.
- **llama.cpp (stock) does not support the `kolibri1` architecture**; community GGUFs need a custom patch at upstream commit 836d571. Ollama and LM Studio cannot load them yet.
- On a mid-range Android phone (6–12 GB RAM, UFS storage): weights cannot be memory-mapped in any usable way. Even though only 3.46B parameters are active, MoE routing touches arbitrary experts, so the whole 40–48 GB file would have to be paged from flash. Expect this to fail to load or run at well under 1 token/s; there is no phone-class configuration. Even a 2-bit MLX build (about 20–25 GB, estimate) exceeds phone RAM several times over. For comparison, MiniMed's current LLM catalog tops out at about 1.1 GB (`docs/LOCAL_MODELS.md`), and the e5-small query encoder is 118 MB.
- The report names no smaller or dense release; the blog mentions only the earlier Kolibri Origin (30.6B total, 3.27B active, still far too large).

## 3. Fit in MiniMed

| Role | Verdict | Reason |
|---|---|---|
| Query embedding (replace e5-small) | No | Generative model; no embedding head, no trained retrieval objective. Mean-pooled hidden states of a 78B LLM would be far worse than a purpose-trained encoder and impossible to run on device anyway. |
| Cross-encoder reranker (roadmap item 8) | No | Not trained as a reranker; size is 2–3 orders of magnitude above the "small on-device cross-encoder over top 20" in `docs/SEARCH_ROADMAP.md`. Right candidates there are bge-reranker-v2-m3-class or other sub-300 MB multilingual cross-encoders with Russian coverage. |
| Query rewriting / complaint to clinical facts | No (on device) | Cannot run; Russian weak; generation is excluded from the search path. |
| Summarisation as a separate draft artifact (AGENTS.md) | Only as an offline data-side tool, and not recommended | Could run on a workstation with 2x80 GB GPUs (or heavy quantization on a large-RAM Mac) but Russian clinical prose is unevaluated, and AGENTS.md data-agent rules forbid harmonising source claims. A Russian-strong open model would be a better choice for any draft-artifact experiment. |
| Dictation | No | Text-only, no speech component. |
| Synthetic query generation for training/eval of e5 (offline, workstation) | Marginal | The only plausible use: generating Russian complaint-style queries for КР. But German/English-centred, so Qwen/Vikhr/other Russian-capable models are the better first choice. |

Comparison with the current pipeline: e5-small (multilingual-e5, 100+ languages including Russian, 118 MB q8,
Q1 test R@5 0.497 for КР) is a purpose-built retriever running in the WebView. Kolibri-1 offers none of: Russian support, retrieval
training, a mobile-size footprint, or an ONNX/GGUF path in stock tooling.

## 4. Is an experiment worth it?

No. If an experiment were forced, it would be the Q1 held-out set (RuMedPrime complaints, RuCCoD diagnoses; test R@5 for КР) with
Kolibri used as an offline query-expansion step on a workstation. Cost: one day to stand up a patched llama.cpp or vLLM on 2x80 GB
(rental GPU), plus the benchmark run. Expected outcome: no gain on Russian queries, and no way to ship it. A better use of
that effort is the roadmap's own item 8 with a small multilingual cross-encoder (size and latency measured first).

## 5. Risks

- **Russian**: no evidence of support; training data and tokenizer target English/German; SFT includes only 2.4 % other languages. Medical Russian terminology and ICD/КР wording are especially unlikely to be handled well.
- **Size/runtime**: 47.5–78 GB; needs unmerged llama.cpp patches; no ONNX.
- **License**: Apache 2.0 on weights, no obstacle (the Apache terms still require keeping notices if redistributed). Not a blocker, but irrelevant given the other points.
- **Medical safety**: card says output must be human-reviewed; hallucination risk; AGENTS.md forbids generated text replacing source material. The model's "grounding with abstention" is untested on Russian clinical text.
- **Provenance/maturity**: released 3 days before this review; community quantizations and tooling are immature.
